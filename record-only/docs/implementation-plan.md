# 刷卡登记版实施与问题处理计划

日期：2026-10-29。**状态：集成环境的业务实现与自动化门禁已落地；真实输入与实机验收仍按 TBD 保留。** 本计划仅适用于 `record-only/`，以 [opinions.md](../opinions.md)、后续用户确认和[业务规格](specification.md)为依据；不依赖其他目录的方案。逐项实测结果见[测试报告](verification-report.md)。

## 审查结论修正

撤回此前第 3 项中要求校园 API 额外提供“绑定证明”的判断：按正常 HTTPS 请求/响应对应关系和接口 schema 处理即可，供应方不返回卡号字段不构成缺陷。若实际协议返回卡号引用，按协议做普通一致性校验。

撤回此前第 4 项把“伪造刷卡请求”单独列为严重问题的判断：未知或停用卡号重算出的 studentId 会被内部授权检查拒绝，与读取未知卡的处理一致。本版不增加读卡器硬件证明、签名读卡或另建卡凭证系统。服务端保留正常的登录、输入校验、ID 重算和内部授权检查即可。

共享教师账号、固定盐哈希学生 ID、原卡号只经 HTTPS 临时查询、不提供备份/导出，均是已确认的设计。本计划不重新将这些选择列为待批准项。其余事项采用下列处理方向，不再悬置为架构争议。

## 关键处理细则

### 1. 刷卡、provider 与预置

服务端在查 provider **之前**完成内部授权。已知且启用的有效刷卡每次刷新资料，不以缓存代替；provider 调用仍在数据库事务外。提交资料刷新时，在短事务内重新检查学生状态及版本，防止查询期间发生停用后仍放行。按 studentId 的串行队列限制并发、设置超时并在完成后释放；不能留下无限增长的锁对象或原卡号引用。

适配器使用固定 HTTPS 目的地、正常 TLS、供应方认证和有限超时；校验成功状态、单一结果及白名单必填字段。响应若按协议包含卡号引用就验证一致，否则直接以本次调用上下文关联，**不要求新增字段或额外绑定证明**。失败不覆盖旧资料、不生成可提交预览。原卡号和完整响应在完成/失败/取消后释放，不进入日志、磁盘或重试队列。

seed 只接受来源明确的授权学生输入，先校验 ID 格式、hashVersion/issuer、重复和冲突，再用 ORM 事务写入。若输入仅有哈希 ID，必须确认生成规则兼容；若需从卡号生成，则仅在受控处理内存中使用，结果只保存哈希和白名单档案。失败整批回滚，重复执行同一输入不重复插入，冲突必须报告；不自动启用已停用学生、不覆盖正常刷卡刷新的档案。首版换卡规则仍按 NEXT-01 延期，新卡无预置即拒绝。

### 2. 网络、存储与发布

Compose 网络限定本项目容器，数据库网络不连接 gateway，不允许无关服务加入。只发布 gateway 的 LAN 443；API/PG/日志接收无宿主发布端口，服务容器无 Docker socket。校园 API 的出口和证书校验单独配置。这里的内部 HTTP 是已接受的同宿主信任边界，不作“每个链路都端到端 HTTPS”的错误宣传。

`pgdata`、来源 spool、ingest 游标、客户端 outbox/提交意图都必须有稳定持久位置。正常发布禁止删除卷或改项目名误接空库；升级先验证兼容性，单一 migrate 作业失败则不接流量。DB 或容器重启后核对现有记录与原 requestId 的结果，不以重新建库代替修复。损坏磁盘或被删除的卷不属于本版可自动恢复能力，不新增产品备份模块。

### 3. 日志容量、ACK 与压力状态

采集以下指标：各来源待传条数/字节、最老未 ACK 年龄、上传/归集成功率、DB/日志卷/客户端磁盘可用空间及 inode（适用时）。命名卷不等于独立磁盘；如果 DB 和 spool 共用宿主文件系统，必须合并核算占用并监测底层剩余量，避免只看逻辑配额。

容量按实测峰值日志字节率 × 运维允许的最长中断窗口，加上业务数据增长、归集追赶时间和预留空间计算。先给出可配置水位与恢复滞后量，具体值在 PLAN-08 的目标机器测试后固定；不凭测试客户端数量宣称容量上限。上线前由部署负责人填定容量、水位和可容忍中断窗口，长期保留/删除政策仍为 TBD-05。

| 状态 | 服务端处理 | 教师端表现与处理 |
| --- | --- | --- |
| 正常 | 日志接收事务持久提交后 ACK；重复 logId 返回已接收结果；已 ACK 来源段才可回收 | 持久队列自动补传；显示待传数量与最近成功时间 |
| 容量预警 | 到达预警水位或积压年龄阈值，持续归集/补传，通知运维检查空间、网络与 ingest | 显示警告及待传状态；有持久能力时业务正常，不重复生成同一告警风暴 |
| 受限写入 | 到达保留水位，暂停新登记、资料刷新及非必要修改；已有记录的手动/批量结束仅在完整业务、审计、操作结果和必要日志仍可可靠保存时允许 | 禁止刷卡创建新预览，保留可用的查询/手动结束；说明限制原因，不伪装成学生无权限 |
| 持久写入失败 | 存储不可写或无法保证原子提交/必要日志保存时，拒绝对应写入，不发虚假 ACK；可用读请求仍服务 | 显示明确错误；客户端若不能持久保存提交意图/必要日志也不发新命令；已发命令标记结果待确认 |
| 恢复 | 写入探测通过且空间回到恢复水位后解除限制；恢复稳定 ID 补传与去重 | 重新认证（如需）→ 查原 requestId → 刷新列表；未提交刷卡预览重新刷卡 |

压力状态通过已认证的 `GET /api/v1/service-status` 返回业务可用性、`allowedActions` 与原因码，前台随列表轮询，不以全站 readiness=503 屏蔽仍可工作的查询/手动结束；readiness 用于核心 DB/schema 故障，provider 中断和容量预警不触发重启循环。状态响应仅暴露业务可用性和原因码，详细服务器容量指标留给运维。磁盘满且读服务仍可工作时，只开放明确允许的只读路由。

所有已生成日志应进入持久补传链路，不以采样、环形覆盖、队列满删除旧项解决积压；生产日志级别仅控制以后是否生成诊断日志。来源轮转只能回收已 ACK 段；归集自身不递归记录每条日志入库动作，告警按状态变化产生。持久介质故障时不能承诺日志零丢失，应明确报告采集失败并限制产生新业务，不能把“无法写入”记为“已经上传”。

运维处置顺序为检查归集/网络/DB → 恢复通路并扩容 → 校验补传 → 解除限制。TBD-05 未确认前不自动删除服务端历史或日志；后续清理只能针对已接收数据按确认的保留规则执行，审计/使用记录/幂等结果的关联和保留必须一致，不能直接让 logrotate 删除未交接的 spool。无需新增教师端运维控制台。

### 4. 故障恢复与未确认提交

| 故障 | 当下行为 | 恢复动作 |
| --- | --- | --- |
| 教师端断网 / 服务端停机 | 页面标出最近更新时间和数据过期；禁止新业务；已发请求显示待确认；日志持久留存 | 同 origin 重新认证后查询原 clientId/requestId；不能生成新 requestId 再做一遍 |
| provider 不可用 | 只停止刷卡登记/刷卡结束，不显示可提交的旧资料 | 恢复后重刷；已有记录可立即从内部列表手动结束，不等待 provider |
| API 重启 / 改密重建 | 内存会话/预览失效，DB 业务与 operations 保留 | 重新登录先查已发提交；已提交返回原结果；未提交/已确认未提交且预览失效须重刷或重新预览 |
| 命令响应丢失 | 不把超时当失败，不自动撤销已提交事务 | 以原键查/重试；`operations` 未找到本身不证明没执行，先由同键提交路径完成仲裁；服务端优先返回已有结果再判断 preview |
| Electron 退出 / 系统重启 | 不将临时刷卡请求变成离线队列 | main 从持久意图恢复普通提交，清理失效页面/预览；日志继续补传；不补记虚构的使用时间 |

## 实施顺序与交付包

1. **基础与接口**：在 `record-only/` 建立 Yarn 4 根工作区及共享 protocol/domain 包、哈希向量、错误码、FakeProvider/FakeCardReader；建立真实 PG/Electron 测试入口。落地 PLAN-01/06 的输入与授权规则。
2. **单机业务闭环**：实现 ORM migrations/seed、登录、刷卡刷新、预览、开始/结束/批量、设备编辑和只读历史；教师接入固定 cyez-ui tarball、pin、IPC、10 秒空闲和 5 秒结束计时。业务、审计、持久结果从一开始同事务实现，日志 outbox/spool 同步建设。
3. **容器与故障闭环**：完成五服务 Compose、PLAN-02/03/04/05，联调真实 pin、重启、并发、ACK 丢失和空间压力；提供部署模板、升级/改密/扩容/故障处理说明。
4. **目标环境验收**：执行 PLAN-07/08，使用真实 provider、读卡器、合法 seed、证书和安装包签名；提交两端独立测试报告、联调报告、容量报告和版本锁定的发布包。任何 blocked 场景明确列出原因，不用 mock 通过冒充上线完成。

当前这次交付只完成计划、规格及图表修订；上面四阶段均未宣称已经实现。详细测试编号与覆盖率标准以 [testing.md](testing.md) 为准，技术依据沿用 [decisions.md](decisions.md) 中已列明的官方资料。
