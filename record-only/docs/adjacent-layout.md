# 相邻试验组：设备编号几何与批量分配契约（实现冻结稿）

2026-11-19 需求：教师可以设置若干学生为“相邻试验组”成员。这些学生刷卡后不立即分配设备，
而是在短时间内可以继续刷更多人的卡；一旦刷到本批次已出现过的卡，代表这一批结束。批次结束后
系统为这一批学生尽量分配两两相邻的座位，无法满足时退到次优解或“尽量集中”。

本文件是实现前冻结的共享契约（设备编号几何、评分等级、布局设置、批次与接口）。服务端与
教师端都必须按这里的分段与评分语义实现，任何改动先改本文件再改代码。

## 1. 设备编号与几何模型

设备编号 `devices.code` 由数字段和连接符组成（例如 `1-21-41`、`3-24-46`），按连接符切段后
从左到右为第 1 段、第 2 段、第 3 段。只有恰好三段、每段都是非负整数（0–99999）且首尾没有
空段的编号参与相邻判定；其余编号视为“几何未知”。

| 区域   | 段落    | 编号范围                                           | 物理含义                           | 编号规则                           |
| ------ | ------- | -------------------------------------------------- | ---------------------------------- | ---------------------------------- |
| 区域一 | 第 1 段 | `[section1Start, section1Start + section1End − 1)` | 四人桌，四个角各一台，桌与桌相邻   | 一桌 `+0..+3`，下一桌继续，见 §1.1 |
| 区域二 | 第 2 段 | `[section2Start, 100000)`                          | 两条长排两两相对，从同一端依次编号 | 奇数号一排、偶数号一排，见 §1.1    |
| 区域三 | 第 3 段 | `[section3Start, 100000)`                          | 四人桌，四个角各一台，桌与桌相邻   | 一桌 `+0..+3`，下一桌继续，见 §1.1 |

默认值：`{ section1Start: 1, section1End: 8, section2Start: 31, section3Start: 41,
allowCrossArea: true, batchWindowSec: 10, batchStudentLimit: 8 }`。设置页可修改，约束：

- `section1End` 是区域一的**宽度**（桌数 × 4），必须是 4 的倍数且 ≥ 8（至少两张四人桌）。
  区域一占 `[section1Start, section1Start + section1End − 1)`；
  默认 `section1Start = 1`、`section1End = 8` 时可用编号是 `1..7`。
- `section1Start` / `section2Start` 只做平移，不改变任何相对关系（默认 1 / 31）。
- `section3Start` 必须落在四人桌起点网格上：`(section3Start − 41) % 4 === 0`，
  即 `41、45、49…`，保证区域三从一张完整四人桌的第一个角开始编号。
  `42` 会让第一张桌只剩 `42、43、44`，因此非法。
- 三段起点互相独立，不存在 `section3Start > section2Start` 之类的顺序要求；
  但**同一段编号不能同时落在两个区域**——判定顺序固定为“区域一 → 区域二 → 区域三”，
  因此 `section2Start` 不要小于 `section1Start + section1End − 1`。

**设备所属区域（房间）的判定**：取**第 1 段**所在区域；第 1 段无归属时
取第一个有归属的段；三段都无归属（几何未知）返回 `null`。
该定义同样用于 `allowCrossArea = false` 时的“同房间”判定，
以及 `domain.deviceArea()` 的返回值。

### 1.1 段内位置与朝向（用户最终确认版）

用户原话：

> 第一组和第三组是四个电脑一个桌子，其中 `1 3`、`2 4` 面对面，`1 2`、`3 4` 相邻，
> 桌子和桌子之间是 `3 5`、`4 6` 背对背。

即区域一 / 区域三的一张桌子是**四人桌**，四个角各一台电脑，两两相对：

```
      桌面
  1 ──────── 3      1 与 3 面对面（长边两端）
  │          │      2 与 4 面对面
  2 ──────── 4      1 与 2 相邻（短边并排），3 与 4 相邻

  3 ──────── 5      3 与 5 背对背（桌与桌之间）
  4 ──────── 6      4 与 6 背对背
```

编号顺序：一桌四台按 `1 2 3 4` 递增，再下一桌 `5 6 7 8`。

```
pos(v)     = v − S + 1        // S 为区域起点：区域一 S = 1，区域三 S = section3Start
t          = pos(v) − 1
desk(t)    = ⌊t / 4⌋          // 第几张四人桌（0 基）
corner(t)  = t mod 4          // 0 = 左上(1)、1 = 左下(2)、2 = 右上(3)、3 = 右下(4)
```

| `corner` | 桌上位置      | 同桌示例 | 相邻桌示例 |
| -------- | ------------- | -------- | ---------- |
| 0        | 长边一端·上   | `1`      | `5`        |
| 1        | 长边一端·下   | `2`      | `6`        |
| 2        | 长边另一端·上 | `3`      | `7`        |
| 3        | 长边另一端·下 | `4`      | `8`        |

同一张桌上的两类关系（**用户明确“`1 2` 是并排，比面对面好”**）：

- **相邻（并排）**：`{0,1}`、`{2,3}` → `1 2`、`3 4`。两人坐在同一条短边上并排，
  中间只隔一点距离，谁都不用转头 —— **全场最好的关系**。
- **面对面**：`{0,2}`、`{1,3}` → `1 3`、`2 4`。两人分坐桌子两条长边的同一端，
  抬头就在对方屏幕对面 —— 次好，讨论方便但需要转头。

桌子与桌子之间：

- **背对背**：`{2,0}`、`{3,1}` 与**下一张桌**之间 → `3 5`、`4 6`。前一张桌的远端与后一张桌的
  近端背对背，两人谁也看不到对方屏幕 —— 属于“相邻”但质量最差的一档。
- **斜对角**：`{0,3}`、`{1,2}` → `1 4`、`2 3`。**用户明确说斜对角很差**，排在背对背之后。

区域二（两条长排，中间是空档，从同一端起顺序编号）：

```
31 33 35 …
------------
32 34 36 …
column(v) = 0 若 v 为奇数（上排），1 若 v 为偶数（下排）
index(v)  = ⌊(v − 1) / 2⌋      // 从同一端起算的列号（0 基）：31→15、32→15、33→16
```

`31` 与 `33` 同排相邻（侧头可见），`31` 与 `32` 隔空档正对（要隔着空档看）。
长排上不存在“并排看同一块屏”或“面对面”的便利，所以区域二最好也只有中间档。

### 1.2 相邻关系与优先序（以“看不看得见对方屏幕”为唯一标准）

用户原话：

> 面对面也不好啊，因为还是看不到对方屏幕；肩并肩最好，就是如果有桌子或者长排能排列在一起的最好；
> 如果不行并且人 ≤ 4 这类就直接放在两张桌子的能看到对方屏幕的地方，例如 `3 4 5 6`；
> 如果再多一点再想其他的分配方法，但是长桌的两侧要绕到对面很差，如果只是长桌中间有一个人用了可以跳过。

判定标准只有一条：**两个人坐着时能否直接看到对方的屏幕**。

| 序  | 关系            | 条件                                                                                   | 例子                       | 能否看见对方屏幕                          |
| --- | --------------- | -------------------------------------------------------------------------------------- | -------------------------- | ----------------------------------------- |
| 1   | `side-by-side`  | 四角桌：同 `desk`、`corner` 为 `{0,1}` 或 `{2,3}`；区域二：同 `column`、`index` 相差 1 | `1 2`、`3 4`、`31 33`      | **能**，肩并肩，一眼同屏                  |
| 2   | `corner-facing` | 四角桌：`desk` 相差 1、前桌 `{2,3}` ↔ 后桌 `{0,1}`                                     | `3 5`、`4 6`               | **能**，相邻两桌的角对角，回头/侧身可见   |
| 3   | `long-row-skip` | 区域二：同 `column`、`index` 相差 2 且中间位不可用                                     | `31 35`（`33` 被别人占着） | **能**，隔一个空位仍可侧头看              |
| 4   | `face-to-face`  | 四角桌：同 `desk`、`corner` 为 `{0,2}` 或 `{1,3}`；区域二：不同 `column`、`index` 相同 | `1 3`、`2 4`、`31 32`      | **不能**，隔着桌面/空档，看到的是对方的脸 |
| 5   | `across-row`    | 区域二：不同 `column`、`index` 相差 ≥ 1                                                | `31 34`、`31 36`           | **不能**，要绕到整排对面                  |
| 6   | `diagonal`      | 四角桌：同 `desk`、`corner` 为 `{0,3}` 或 `{1,2}`                                      | `1 4`、`2 3`               | **不能**，斜对角                          |
| —   | `none`          | 其余全部情形                                                                           | 隔桌、隔位、几何未知       | 不相邻                                    |

**等级映射**（`AdjacencyRelation` → `AdjacencyGrade`）：

| 关系                                    | 等级        | 中文标签                       |
| --------------------------------------- | ----------- | ------------------------------ |
| `side-by-side`（`1 2`、`3 4`、`31 33`） | `excellent` | 完全相邻（肩并肩）             |
| `corner-facing`（`3 5`、`4 6`）         | `good`      | 较优相邻                       |
| `long-row-skip`（`31 35`，中间空一位）  | `fair`      | 次优相邻（长桌隔一空位）       |
| `face-to-face`（`1 3`、`2 4`、`31 32`） | `degraded`  | 勉强相邻（面对面，看不见屏幕） |
| `across-row`（`31 34`）                 | `degraded`  | 勉强相邻（要绕到对面）         |
| `diagonal`（`1 4`、`2 3`）              | `degraded`  | 勉强相邻（斜对角，看不见屏幕） |
| `none`                                  | `none`      | 不相邻                         |

**关键结论（与用户诉求一一对应）**：

1. **肩并肩永远最优**：四角桌的 `{0,1}`/`{2,3}` 与区域二同排相邻都属于 `excellent`。
2. **人 ≤ 4 且排不成一排时**，用“两张桌子的能看到对方屏幕的地方” = `corner-facing`，
   即 `3 5`、`4 6` 这类跨桌角对角，等级 `good`。这正是用户举的 `3 4 5 6`：
   `3 4` 肩并肩（excellent）+ `5 6` 肩并肩（excellent）+ 跨桌角对角（good），整批落在 `good`，可用。
3. **面对面 / 斜对角 / 绕到对面**都属于“看不见屏幕”，统一降为 `degraded`，
   只在 `excellent`/`good`/`fair` 都凑不出来时使用，并且教师端必须显示为“勉强相邻”。
4. **长桌中间被占用可以跳过**：`long-row-skip` 允许中间隔一个已占用的座位，仍算 `fair`，
   明显好于绕到对面（`degraded`）。

### 1.3 分配优先级（`planSeats` 的搜索顺序）

用户补充要求：**“我希望三个人就直接尽量排在长桌上”**——区域二的两条长排能一路排开，
比在四人桌上东拼西凑好。因此排序在“能否看见屏幕”之上再加一条**形状偏好**：
**能连成一条不间断的座位线（长排 / 长边）＞ 靠得多近**。

按顺序尝试，取第一个可行方案：

1. **`excellent`**（全员两两肩并肩，`run` 越大越优先）：全员坐在同一条长排的连续座位上
   （区域二同一 `column`、`index` 连续）时 `run` 等于人数，直接判定整批 `excellent`——
   **这条豁免优先于“两两取最差”**；凑不成整排时退化为成对肩并肩（`run = 2`）；
2. **`good`**：肩并肩 + 相邻两桌角对角（`3 5`/`4 6`），人 ≤ 4 且桌边排不开时用；
3. **`fair`**：长桌中间座位被占用时跳过一格继续同排；
4. **`degraded`**：只剩面对面 / 斜对角 / 绕对面时才用；
5. **`clustered` / `scattered`**：完全排不出相邻时，按区域内编号极差 `span` 尽量集中，或分散。

**“连成一条线”的定义**（`Run`）：方案内同一个区域内、同一排（区域二同一 `column`；
四人桌同一 `corner` 两侧）上**座位号连续**的最长相邻人数。`run ≥ 3` 视为“排成了一排”。

同等级内依次比较（字典序，先满足前者）：

1. `run` 大者优先（越能连成一条线越好）；
2. `span` 小者优先（越集中越好）；
3. 座位编号字典序小者优先（结果稳定可复现）。

**3 人批次的预期结果**：若区域二有 ≥ 3 台同排空闲设备，必然选成一条长排上的连续三台
（`excellent`、`run = 3`），而不是四人桌上的 `3 4`+跨桌角对角（`good`）。
长排不够时（例如都被别人占着）才退回四人桌的 `good` 方案。

> **2026-11-19 修订（第五次）**：此前 `planSeats` 只按等级 + `span` 排序，三人会选
> `3 4 5`（`excellent`+`good`，整批 `good`）。加入 `run` 维度后，三人优先坐成长排，
> 这条优先级高于“等级更高但零散”——因为用户明确说“三个人就直接尽量排在长桌上”。

## 2. 评分：从最优到次优

服务端枚举“把本批次学生逐个放到可用设备上”的方案，按 §1.3 的等级 0 → 5 依次尝试，
取第一个可行等级；同等级内按 `run` 大 → `span` 小 → 座位编号字典序小依次比较，
结果稳定可复现。

| 等级 | 名称        | 含义                                                       |
| ---- | ----------- | ---------------------------------------------------------- |
| 0    | `excellent` | 所有配对都能肩并肩看到屏幕（`1 2`/`3 4`/`31 33`）          |
| 1    | `good`      | 最差的一对是相邻桌角对角（`3 5`/`4 6`），回头可见屏幕      |
| 2    | `fair`      | 最差的一对是长桌隔一空位（`31 35`，中间座位被占）          |
| 3    | `degraded`  | 最差的一对是面对面 / 斜对角 / 绕到对面——**看不见对方屏幕** |
| 4    | `clustered` | 完全排不出相邻：按区域内编号极差 `span` 尽量集中           |
| 5    | `scattered` | 连集中也做不到：仅保证每人有座位                           |

同等级内按 §1.3 的次序比较：`run`（能连成一条线的最长人数）大者优先 → `span` 小者优先 →
座位编号字典序小者优先。`run ≥ 3` 表示本批坐成了一整排，优先于任何零散的相同等级方案。

`degraded` 排在 `clustered` 之前：面对面至少还坐在相邻两张桌子旁，交流比分散在机房各处强，
但**必须显著劣于所有能看见屏幕的组合**。

`clustered` 的 `span` 按区域分别累计（区域一、二、三各自的座位编号极差），总和越小越集中。
`planSeats` 的最差档位是 `clustered`；`scattered` 只由单次方案评分 `scoreArrangement` 产出。

**同房间约束**：默认把“区域”当作房间；跨区域的一律降级到 `degraded`，
避免把学生分到不同房间讨论。设置里 `allowCrossArea` 可以放开这一限制。

## 3. 批次（batch）语义

1. 只有“相邻试验组”成员（`students.experiment_group = true`）才触发批次收集；普通学生
   刷卡仍走原有单人次登记/结束流程。
2. 第一位成员刷卡后，服务端返回 `mode: "batch"` 的批次预览，`closesAtMs = 现在 + 窗口`；
   该学生不分配设备。
3. 窗口内继续刷卡：新成员加入批次；重复卡表示“批次结束”，立即分配并列结果。
4. 批次结束条件（任一）：刷到重复卡；窗口超时（=`closesAtMs`）；教师点“结束批次并分配”。
5. 窗口默认 **10 秒**（设置页可改 10–600 秒），每次成功加入成员**不延长**窗口。
   10 秒是现场连刷的实测节奏：窗口太长会让后面的同学空等，太短又会把正常连刷当成超时。
6. 批次内出现“已在座使用中”的成员时，不参与本次分配，结果中标注 `busy`。
7. 分配结果里每个学生占一台设备，`startedAtMs` 统一取批次确认时刻，避免区间重叠冲突。

## 4. 布局与批次设置

| 键               | 默认 | 约束                                                                 |
| ---------------- | ---- | -------------------------------------------------------------------- |
| `section1End`    | 8    | 区域一桌数 × 4：4 的倍数，8 ≤ x ≤ 96                                 |
| `section3Start`  | 41   | 四角桌起点网格：41 ≤ x ≤ 9960 且 `(x − 41) % 4 === 0`（41、45、49…） |
| `allowCrossArea` | true | 允许跨区域分配（否则跨区域相邻降级）                                 |
| `batchWindowSec` | 10   | 10–600（默认 10 秒：多人连刷等待过久会被误判为超时）                 |

设置以 JSON 存到服务端 `settings` 表（键 `layout`），教师端通过
`GET/PUT /api/v1/layout` 读写；读写都需要登录，写入要求 `expectedVersion`。

## 5. REST 契约（本功能新增）

| 接口                                   | 输入                                               | 行为                                             |
| -------------------------------------- | -------------------------------------------------- | ------------------------------------------------ |
| `GET /api/v1/layout`                   | —                                                  | 返回 `{ settings, version }`                     |
| `PUT /api/v1/layout`                   | `{ requestId, expectedVersion, ...settings }`      | 完整覆盖设置，返回新 `version`                   |
| `GET /api/v1/students/experiment`      | `{ search?, page?, pageSize? }`                    | 列出被标记为相邻试验组的学生（只读缓存资料）     |
| `PUT /api/v1/students/:id/experiment`  | `{ requestId, enabled }`                           | 设置/取消单个学生的试验组标记                    |
| `POST /api/v1/scan-previews`           | 原有字段                                           | 试验组成员返回 `mode: "batch"` 的 `BatchSession` |
| `POST /api/v1/scan-previews/:id/join`  | `{ scanId, studentId, hashVersion, card, source }` | 批次内继续刷卡；成功时同 `scan-previews` 语义    |
| `POST /api/v1/scan-previews/:id/close` | `{ requestId }`                                    | 教师主动结束批次                                 |
| `POST /api/v1/batches/:id/confirm`     | `{ requestId }`                                    | 结束并分配，返回 `BatchAssignment`               |
| `GET /api/v1/batches/:id`              | —                                                  | 查询批次当前状态                                 |

`BatchSession`：`{ id, mode: "batch", atMs, closesAtMs, students: StudentDTO[], duplicates: [],
state: "collecting" | "closed" | "assigned" }`。

`BatchAssignment`：`{ batchId, grade, gradeLabel, assigned: { studentId, deviceId, code }[],
busy: studentId[], unresolved: studentId[], span }`。

错误 code 追加：`EXPERIMENT_GROUP_DISABLED`（该学生不在试验组）、`BATCH_FULL`（单批上限）、
`BATCH_CLOSED`、`BATCH_NOT_FOUND`、`LAYOUT_VERSION_CONFLICT`、`DEVICE_GEOMETRY_INVALID`。

单批上限 `batchStudentLimit`（默认 8 人，可配置）。

## 6. 本地（教师端 main）职责

- 维护“当前批次”的内存状态与截止时间，与刷卡窗口共享。
- 批次期间的刷卡不再改变管理后台的门控页面，只更新批次预览。
- 教师关闭刷卡窗口、退出登录、切换服务器时撤销批次并删除对应服务端预览。
- 批次分配成功后，教师端打印/展示分配结果，学生端（本阶段无学生客户端）由教师引导。

## 7. 历史修订

本节只保留演进记录；**实现位置与当前取舍见 §8**。

**2026-11-19 冻结**：`layoutSettingsSchema.section3Start` 原先同时要求“≥ 41”和“偶数”，
与默认值 `41` 冲突，导致 `DEFAULT_LAYOUT_SETTINGS` 无法自校验。现统一为**四角桌起点网格**
`(section3Start − 41) % 4 === 0`（41、45、49…）：`41/45/49` 合法，`42/43/44/40` 非法。
`42` 会让第一张桌子只剩 3 个角，与“完整四角桌”矛盾。

同时 `section1End` 的下限由 4 提高到 **8**（区域一桌数 × 4，至少两张完整四角桌）：
`section1End = 4` 时区域一只剩 3 个角，凑不满一张桌子。

### 8.2 已定稿的契约细节

1. **布局设置七元组**（§4）：
   `{ section1Start: 1, section1End: 8, section2Start: 31, section3Start: 41,
allowCrossArea: true, batchWindowSec: 10, batchStudentLimit: 8 }`。
   - `section1Start` / `section2Start` / `section3Start` 是三个区域各自的起始编号，都可在设置页修改；
   - `section1End` 仍是区域一的**绝对上界**（`S1 = 8` ⇒ 区域一 `1..7`），不随 `section1Start` 改变语义；
   - `section3Start` 仍须满足 `(S3 − 41) % 4 === 0`（`41、45、49…`），因为它是四人桌起点网格；
   - `section1End` 仍是 4 的倍数且 `≥ 8`（至少两张四人桌）。
2. **关系 → 等级**（§1.2，实现即文档）：

   | 关系                                       | 例子                                         | 等级        |
   | ------------------------------------------ | -------------------------------------------- | ----------- |
   | `side-by-side`                             | `1 2`、`3 4`、`5 6`、`31 33`                 | `excellent` |
   | `corner-facing`                            | `3 5`、`4 6`、`7 9`                          | `good`      |
   | `long-row-skip`                            | `31 35`（中间座位被占）                      | `fair`      |
   | `face-to-face` / `across-row` / `diagonal` | `1 3`、`2 4`、`31 32`、`31 34`、`1 4`、`2 3` | `degraded`  |
   | —                                          | 其余                                         | `none`      |

   等级数组：`["excellent","good","fair","degraded","clustered","scattered"]`，
   `GRADE_RANK.degraded === 3`、`clustered === 4`、`scattered === 5`。

3. **`deviceArea` 语义**：取第 1 段所在区域；第 1 段无归属时取第一个有归属的段；
   全部无归属返回 `null`。`deviceArea("1-0-0") === 1`、`deviceArea("0-31-0") === 2`。
   `allowCrossArea = false` 时的“同房间”判定以它为准。
4. **座位规划的评分口径**：`grade` 取方案内**全部两两配对**关系的最差者；
   任一对跨区域即 `crossArea = true` 并把等级封顶到 `degraded`。
   **唯一豁免**：全员落在同一段连续长排上（`run ≥ 人数`）时整批判 `excellent`，
   不受跨区域封顶影响——这正是“三个人尽量排在长桌上”的落点。
5. **`planSeats` 复杂度**：预计算 `n×n` 关系矩阵 + 组合 DFS 分支限界
   （增量最差关系下界、span 单调剪枝、等级 0 早退、贪心初始上界），
   另有节点硬预算，最坏情况返回确定结果、不抛异常。
6. **批次路由 schema 命名**：`POST /api/v1/batches/:id/confirm` 使用
   `batchAssignConfirmSchema`（`{ requestId }`）；既有的 `batchConfirmSchema`
   （整批结束使用记录）保持不变，二者语义不同。
7. **`planSeats(1..8, 4)` 的期望结果**：`["3","4","5","6"]`、等级 `good`。
   整桌 `1 2 3 4` 含 `1 3`/`2 4`（`degraded`），所以四人批应优先坐到
   “两张桌子的角对角位置”，这正是用户举的 `3 4 5 6` 例子。
