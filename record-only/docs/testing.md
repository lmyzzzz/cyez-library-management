# 服务端与客户端测试设计

**服务端和客户端分别必须具有单元测试与集成测试。** 本轮提交的是验收计划，尚无业务实现，以下测试均为待实现/待运行；现有图表生成校验不能计入产品测试通过数。

## 分层与工具

| 层次 | 测试对象与真实边界 | 工具/环境 |
| --- | --- | --- |
| S-U 服务端单元 | 时间转换、卡规范化/HMAC、领域规则、备注合并、字段白名单、权限判断、错误映射 | Vitest；确定性假时钟/ID/provider，不访问生产秘密或资料 |
| S-I 服务端集成 | 路由 schema/认证/业务服务/真实 repository/真实 PostgreSQL；事务、约束与迁移 | Fastify `inject()` + 临时 PostgreSQL 容器；另起真实 TLS/gateway 请求验证网络边界 |
| C-U 客户端单元/组件 | 页面门控、计时器、单次提交、设备选择、reader 解析、preload schema、日志队列控制 | Vitest、Testing Library；fake reader/clock/network；纯规则与 React 组件分别测试 |
| C-I 客户端集成 | 真实 Electron main/preload/renderer、临时 userData、实际 SQLite 日志/意图持久化、网络序列化、IPC 权限 | Windows CI/专用测试机；Playwright Electron（实验性，固定版本）；可控 HTTP 测试服务与 FakeCardReader |
| E2E 两端联调 | 打包客户端 + Docker gateway/API/PG；完整登记/结束/批量/断网/重启 | 临时测试环境、种子数据；FakeProvider 与 CardReader 适配测试入口，不访问真实校园 API |
| H/W 硬件与运维 | 实际 USB、驱动/拔插、多窗口/DPI、安装签名、Linux 部署/恢复 | Windows/Linux 目标实机；TBD-02/03/04 闭合后运行；不能由 mock 测试替代 |

API 集成不能用 SQLite 替代 PostgreSQL，客户端集成不能只在 jsdom 里渲染页面。SDK mock 只用于单元；TLS、真实 JSON、Electron IPC 和数据库约束必须经过相应集成层。上游 cyez-ui 自带测试不能直接算本项目覆盖率。

## 服务端测试矩阵

| ID | 场景 | 必须断言 |
| --- | --- | --- |
| S-U-01 | UID 长度/前导零/字节序/发行方、HMAC keyVersion | 相同规范输入稳定查找，不同命名空间不碰撞；原 UID/secret 不进入日志；未知读卡协议不擅自规范化 |
| S-U-02 | 毫秒整数、null 结束、时区与时间反序 | DTO 无字符串时间戳，拒绝非安全整数/负时长；显示时区不改变存储时刻 |
| S-U-03 | 活动/空闲/禁用/归档组合、学生最新资料 | 禁用使用中仍保留占用；旧记录读新资料；不把 tag 当授权 |
| S-U-04 | 批量备注空/非空、请求摘要、状态错误 | 精确追加一次，空公共备注保留原文；同键不同 payload 拒绝 |
| S-I-01 | 同学生/同设备并发开始，多账号竞争 | 真实并发连接后最多一个成功活动记录；失败事务无孤儿学生/记录；条件唯一索引生效 |
| S-I-02 | 开始与禁用/归档、标签删除同时发生 | 行锁/外键/统一锁顺序保持一致；不会出现已禁用却分配成功的未经定义状态 |
| S-I-03 | 提交前断线、提交后响应丢失、重启后同键重试 | 操作结果持久可查；重试不重复记录/审计/备注；preview 过期不影响已提交结果查询 |
| S-I-04 | 结束与备注编辑/重复结束竞争 | expectedVersion 冲突明确；只结束指定 recordId，不结束后来的新记录 |
| S-I-05 | 批量固定集合、并发新增、一个成员变更 | 新增记录不入批次；任一冲突单批全回滚；跨批结果透明；追加备注不重复 |
| S-I-06 | 资料更新/归档、标签关联变更 | 两向关系一致、无重复和孤儿；历史显示最新资料，归档保留 FK |
| S-I-07 | provider 超时/错误/额外敏感字段、未知卡取消 | 服务端独占 provider 凭证；只存允许字段；失败/取消无半条业务，不存完整响应 |
| S-I-08 | 认证失效、越机房、只读/普通用户管理请求、过大 body | 401/403/413/422 等明确；无越权导出、SQL 注入或敏感信息回显 |
| S-I-09 | 日志 ACK 丢失/部分失败/DB 不可写 | 稳定 ID 去重、提交前不 ACK；恢复补传；访问日志不包含卡号或 token |
| S-I-10 | 空库迁移、已有数据升级、失败迁移、备份还原 | schema 和数据完整；失败阻断 API ready；归档/占用/凭证/操作记录可还原 |
| S-I-11 | 同 preview 换 requestId、并发提交、成功后结束再重用、重启后重用 | intentId 只被成功事务消费一次；旧 preview 不能创建第二条使用记录；同键仍能取回结果；批量单元各自幂等 |
| S-I-12 | 先刷卡再结束目标设备、历史补录/更正、HMAC 轮换双键并发 | 重叠区间拒绝且提示重刷，等值结束/开始边界可用；所有操作遵守对象锁；新旧 HMAC 别名不分裂学生身份 |

## 联调、CI 与完成标准

联调必须走“刷未知卡 → 必需资料 → 选设备 → 开始 → 再刷卡 → 结束”，同时覆盖已知卡、取消、资料缺失、手动单结束、批量追加、两教师抢同机、后建记录排除、应用/服务重启与补传。硬件文档到位后加入实际 UID 格式、连续读卡、拔插、设备多实例及驱动权限测试；未测硬件不宣称可上线。

CI 拆为独立任务：

1. 文档/图源再生成检查、格式/类型检查、不可变 Yarn 安装。
2. `test:unit:server` 与 `test:unit:client` 独立报告；所有业务分支指定 ID 与断言，不只测 getter/快照。
3. Linux `test:integration:server` 启临时 PostgreSQL/Compose；每次唯一 project 名/数据库与清理范围，禁止指向真实服务器。记录迁移版本、seed 与数据库日志。
4. Windows `test:integration:client` 启真实 Electron 与测试 HTTP 服务；独立 userData/日志目录；不接受“没有桌面所以全部跳过”却标绿。
5. 构建 Docker 镜像与客户端包，执行两端联调和部署烟测；输出 test report、coverage、失败截图/trace、镜像 digest、依赖版本及源 commit，不包含个人数据。

实现阶段在各工作区声明对应脚本并由根 Yarn 调度；本轮不存在这些脚本，不给出可直接运行成功的虚假命令。产品完成门槛：服务端和客户端分别 lines/statements/functions ≥85%、branches ≥80%；关键身份、占用、幂等、权限、倒计时和备注模块 branches ≥90%。阈值是本项目初始质量要求，可经评审调整；生成代码/第三方包明确排除，不能排除失败路径凑覆盖率。集成测试使用行为清单做门禁，不以代码覆盖率替代。

所有 P0 场景必须通过且无跳过；重试成功的 flaky 用例仍报告并处理。尚未接入 provider/读卡硬件的用例明确标为 blocked by TBD，不能假实现后计为通过。发布还须完成目标 Windows 安装/卸载/升级、TLS、Docker 卷持久性与恢复演练，许可/签名见 TBD-06。

P0 明确包括 S-I-01～05、S-I-07～12，C-U-01～03、C-I-03～06，以及完整登记/结束联调与备份恢复；其余矩阵用例同样是完成标准，不能因未标 P0 就长期不实现。
