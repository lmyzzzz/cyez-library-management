# 学校图书馆机房管理系统

面向多机房的管理系统设计，不设置学生端或教师端数量的产品上限。服务端部署在固定 IP 的机房服务器，教师端通过动态地址注册；学生端主要逻辑位于 Electron 应用内，Rust Windows 服务仅作为具有固定功能和本地状态机的离线守护进程。

服务端与 Electron 应用统一使用 TypeScript，采用现代 Yarn 4.x workspaces 组织共享协议、运行时校验和业务规则。首轮负载测试使用 200 台学生机、2 个教师端，该规模不是客户端数量限制，也不是无限容量的性能承诺。

本系统所有组件产生的全部日志集中保存到服务端，覆盖教师端、学生端、Rust 守护进程、安装/更新执行器及服务端自身的各级日志。客户端离线时持久缓存并补传；Rust 保持离线，由学生 Electron 导入并上传其全部日志。

**当前阶段：架构设计，尚未实现客户端、服务端或防护功能。**

## 已确认的设计约束

| 项目 | 设计决定 |
| --- | --- |
| 客户端数量 | 不设产品上限；200 台学生机、2 个教师端仅为首轮负载测试基线 |
| 语言与工程 | TypeScript + Yarn 4.x workspaces；内部依赖使用 `workspace:` 协议，Rust 独立使用 Cargo |
| 学生端职责 | Electron 负责通信、Session、授权校验、日志、屏幕采集与传输、更新协调；Rust 仅负责本地守护状态机、进程监督和系统动作 |
| 日志归集 | 所有组件、所有已产生日志均进入服务端；断网补传，未经持久确认不得静默丢弃；诊断日志不直接改变 Session |
| 系统兼容 | 学生机 Windows 10 及以上，不依赖企业版、教育版等专属功能；具体构建与硬件须实测 |
| 网络监督 | 每 1 秒心跳；服务端或当前控制教师端连续失联 20 秒即锁机 |
| 必需进程 | 指定程序必须持续存活；退出即锁机，不是限制其他程序运行的应用白名单 |
| 故障恢复 | 保留原 Session 并暂停计时；连接和进程恢复后仍须教师重新授权 |
| 锁机程序故障 | 非预期退出、持续无响应或锁定失败时请求关机，并记录防护故障 |
| 首版监控 | 低帧率屏幕墙、单机放大、解锁、锁定、结束使用和关机；不含远程键鼠 |
| 后续接入 | 人脸算法与 Electron UI 组件库通过适配接口接入 |

## 防护能力边界

学生持有本地管理员权限，且本项目不开发内核驱动。Rust 服务将采用权限收紧、进程监督和服务恢复等尽力防护措施，但**不能保证阻止管理员停服、删除程序或同时结束服务与界面**。Electron 全屏和键盘钩子也不能保证阻止所有 Windows 系统入口。

断电或长按电源可能来不及上报。此类情况先记录“原因待确认”，不能仅凭失联认定正常结束或恶意使用。详细规则见[故障处置与关机证据](docs/architecture.md#故障处置与关机证据)。

原始讨论草图保留在仓库根目录，正式设计以 `docs/architecture.md` 为准。本文描述的是设计目标，实机防护、兼容性与容量结果须在实现后另行验证。
