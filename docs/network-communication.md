# 按身份整理的三端网络通信

设计基线：2026-10-23。本文按服务端、教师端、学生端整理全部已确定的系统网络通信，是[架构正文](architecture.md)的通信清单。当前仍为设计阶段；接口族用于划分职责，除正文已明确的路径外，不代表 HTTP 路由或 WebSocket 消息名已经实现。

## 身份与建连方向

**建连方向与业务消息方向分开理解：教师端和学生端主动连接固定地址服务端；学生端主动连接教师端，教师命令沿学生建立的双向连接发送。** 服务端通过现有客户端连接推送通知，不需要反向拨号到学生机。首版无需学生端开放远程监听端口。

| 身份 | 证明方式与权限边界 |
| --- | --- |
| 服务端 | 安装配置中的固定地址与受信任 TLS 身份；负责设备凭证、角色、教师权限和业务授权；客户端不能仅凭 IP 相同就信任服务端 |
| 待入网设备 | 先验证服务端 TLS 身份，以一次性注册码或受限待审批流程申请教师/学生角色；获批前没有已注册设备权限，不能查询学生资料、订阅屏幕或执行命令 |
| 教师设备 | 设备证书与服务端登记的 teacher 角色；可以报告本机启动/端点、心跳、上传本机日志和检查适用更新，不等于教师账号已登录 |
| 教师账号 | 登录身份、权限和机房范围；访问学生资料、Session、日志、屏幕、机器操作及服务器管理需分别鉴权，管理权限不是教师角色默认附赠 |
| 控制教师 | 教师设备与账号基础上，对某台学生机持有当前控制租约与 `controlEpoch`；具体机器命令还必须具有服务端签名授权 |
| 只读监控教师 | 持有针对指定设备的短期画面订阅授权；可以收画面，不能据此发送控制命令，也不能续期学生对控制教师的健康期限 |
| 学生设备 | 设备证书与 student 角色；只能报告本机状态/事件/日志、读取适用策略/更新、获取获授权的教师端点，不能自选角色或读取全校资料 |
| Rust / 安装执行器 | 只有本机进程身份与受限本地接口，无远端设备凭证、HTTP/WSS 客户端或远程监听；日志由对应 Electron 代传 |

设备身份、教师账号、控制租约、画面订阅授权分别校验。`bootId`、`sessionId`、`commandId`、IP 和客户端自报角色均不能代替身份凭证。两类 Electron 的网络连接由主进程或应用内工作进程持有；renderer 通过受限 IPC 请求，不自行持有网络凭证。

首次入网尚无设备证书，使用受限申请入口并验证服务端 TLS 身份；获批后的设备通道验证双方受信任身份，设备证书必须与服务端登记的角色及目标设备匹配。教师业务操作还需账号权限或服务端签发的对应操作授权，不能用“证书有效”代替“有权执行”。

| 连接 | 谁主动建立 | 传输及消息方向 | 对外监听方 |
| --- | --- | --- | --- |
| 教师—服务端 | 教师 Electron | HTTPS 请求/响应；WSS 双向状态通知和心跳 | 固定地址服务端 |
| 学生—服务端 | 学生 Electron | HTTPS 请求/响应、日志/事件批传、包下载；WSS 双向策略/目录通知和心跳 | 固定地址服务端 |
| 学生—控制教师 | 学生 Electron | 独立控制 WSS：教师下发命令，学生回执，学生 ping/教师 ack | 当前控制教师的登记端点 |
| 学生—获授权监控教师 | 学生 Electron | 独立画面 WSS：教师发送订阅参数，学生发送缩略图/放大图及采集状态 | 该教师的登记端点；可以是控制教师，也可以是只读教师 |

HTTPS API 统一以 `/api/v1` 为前缀；WebSocket 通过 HTTPS Upgrade 建连。控制与画面可以共用教师的 TLS 监听端口，但必须是独立连接和队列，避免画面拥塞阻塞心跳/命令。服务器上的日志上传与更新下载同样使用独立任务，不挤占健康监督。应用协议版本、消息大小和超时必须校验。

## 服务端身份：接收、校验、返回与推送

服务端作为设备目录、业务授权与持久数据中心，承担以下网络通信。表中的“推送”均指沿客户端已建立的 WSS 发送。

| 对端 / 业务 | 服务端接收 | 服务端返回或推送 | 身份与结果要求 |
| --- | --- | --- | --- |
| 教师/学生：首次入网 | 入网申请、申请角色、注册码或待审批信息 | 审批状态；获批后发设备身份与适用配置 | 初始入口受限；角色由服务端批准，不能接受任意自报角色 |
| 教师/学生：日常启动 | 设备身份、`bootId`、版本、机房、能力和可达端点 | 注册结果、适用策略、协议兼容信息 | 使用已登记设备凭证；应用重启不生成新的设备身份 |
| 教师/学生：设备凭证维护 | 经过现有设备身份验证的续期/轮换请求；失效后的受控重新入网申请 | 新凭证及有效期，或拒绝结果 | 不能靠自报旧 `deviceId` 恢复权限；保留日志等待恢复授权后补传 |
| 教师：地址变化 | 最新 LAN 地址、控制/画面端口与端点版本 | 登记确认；通知相关学生刷新目录 | 端点绑定教师设备身份，IP 只用于寻址 |
| 教师：账号和管理 | 登录/退出/凭证续期请求；设备审批、教师/机房权限、凭证吊销和策略管理 | 账号会话与权限结果、管理操作结果、相关变更通知 | 设备身份与账号权限同时校验；敏感操作写审计 |
| 教师：资料和识别接入 | UID、人工资料、人脸登记/识别适配输入或结果、换卡/删除请求 | 档案、校验结果、识别业务结论 | 依具体人脸适配器确定传模板、引用或输入；不默认调用外部云服务 |
| 教师：Session 与控制 | 登记、机器预留、结束请求；操作权申请/续约/转交；锁定/解锁/关机等命令授权申请 | Session、占用校验结果、租约、签名命令；向相关学生推送控制代次变化 | 事务保证占用与代次；命令授权不等于机器已执行 |
| 学生：发现和状态校准 | 当前控制教师查询、策略版本查询、已安装代次确认、本机状态及命令结果 | 教师设备身份/地址/端口/代次/有效期、适用策略与校准结果 | 学生只能获取本机适用信息；控制接管须等待学生确认 |
| 教师/学生：画面订阅 | 教师申请/续订/取消指定学生画面；学生报告订阅连接状态 | 向双方提供订阅授权；向学生下发教师端点与变更/取消通知 | 只授权和寻址；屏幕数据由学生直达教师，不经过服务端 |
| 教师/学生：日志与事件 | 全部本机日志；学生代传 Rust 日志；各端安装/更新日志；有权上报的业务事件 | 数据持久提交后的逐项确认，或可处理的失败信息 | `logs` 只归档；`events` 校验业务权限并事务提交事件、审计日志与状态投影 |
| 教师：监控和历史查询 | 设备/Session 状态查询及订阅、命令结果查询、日志筛选/分页/导出请求 | 状态快照与后续状态变化、命令结果、日志与统计、上传积压 | 按账号与机房权限过滤；查询日志不等于获得全部管理权限 |
| 教师/学生：版本更新 | 适用版本检查、包下载/续传、更新阶段和结果 | 签名清单、适用安装包、兼容要求与接收确认 | 除 TLS 外，客户端还验证清单签名及包摘要 |
| 教师：服务器运维 | 运行状态、策略/版本管理、备份/恢复等已授权请求 | 运行状态、任务标识、进度和完成结果 | 由服务器自身执行运维任务；不开放任意远程 shell |
| 教师/学生：健康监督 | 每秒应用层 ping、当前启动/连接标识、单调序号 | 匹配当前连接与序号的 ack | 失联只标记连接和证据过期，不能伪造学生锁定或关机完成 |

服务端自身日志经内部接收路径进入中央存储，不必绕一圈 HTTP。服务端访问 PostgreSQL 使用专用数据库身份与受限本机/私网连接；两类客户端均不能直接访问数据库。首版包文件、人脸资料及备份仓库可位于服务器本地，文件读写不计作三端网络通信；若实际选用独立数据库、对象存储或备份服务器，另记录目标、服务身份、端口和 TLS 策略。

## 教师端身份：设备在线、教师业务与学生直连

教师端主动连接服务端，并监听登记过的 LAN 端点，接收学生主动建立的控制/画面连接。设备级上传可在账号未登录时继续，教师业务则必须具有有效账号权限。

| 对端 | 教师端发送 | 教师端接收 | 协议 / 触发条件 |
| --- | --- | --- | --- |
| 服务端 | 首次入网申请；日常启动、版本和能力报告；设备凭证续期/轮换 | 审批/设备身份、注册结果、适用配置与新凭证 | HTTPS；初装、启动、凭证维护或身份恢复 |
| 服务端 | LAN 地址/端口变化 | 地址登记结果 | HTTPS；网卡或 IP/端口改变时；不要等待学生无限重试旧地址 |
| 服务端 | 教师登录、退出、账号凭证续期 | 账号会话与权限结果 | HTTPS；账号操作；账号权限变化使相关授权失效 |
| 服务端 | UID 与学生资料、人脸适配数据、换卡/删除/人工核验 | 档案与校验/识别结果 | HTTPS；录入和登记操作；摄像头/读卡器本地 I/O 不计为网络 |
| 服务端 | 创建/取消/结束 Session、分配机器、控制权申请/续约/转交、命令授权申请 | Session、当前控制代次、租约、签名命令 | HTTPS；教师操作；服务端重新鉴权 |
| 服务端 | 设备/Session/命令状态查询与状态订阅；日志筛选/导出 | 业务状态快照、状态变化、日志、统计与上传积压 | HTTPS 查询，WSS 状态通知；重连后重新取快照校准 |
| 服务端 | 画面申请/续订/取消、可见学生设备集合和画质需求 | 订阅授权、有效期与状态 | HTTPS；翻页、单机放大、关闭页面或授权续期 |
| 服务端 | 本机全部日志及安装/更新日志 | 持久化确认或失败项 | HTTPS 批传；设备身份即可，不依赖当前教师登录；离线留盘补传 |
| 服务端 | 策略、版本发布、账号/设备管理、备份恢复等管理请求 | 结果、任务进度、服务器运行状态 | HTTPS，必要状态通知经 WSS；需相应管理权限 |
| 服务端 | 检查适用版本、下载安装包、上报更新结果 | 签名清单、包文件、接收确认 | HTTPS；启动检查、后台下载、维护阶段上报 |
| 服务端 | 每 1 秒 ping | 匹配的 ack | WSS；连续 20 秒失联停用新操作入口，显示状态失效 |
| 学生控制连接 | 服务端授权的锁定/解锁/恢复/结束/关机命令；对学生 ping 返回 ack | 学生握手、本机状态、命令执行回执、学生每秒 ping | 学生发起的控制 WSS；必须是该设备当前控制教师 |
| 学生画面连接 | 订阅参数、放大/缩略图需求、暂停/取消 | 缩略图/放大图、序号/采集时间、采集错误与新鲜度状态 | 学生发起的独立画面 WSS；控制教师与只读教师均须独立订阅授权 |

教师接收学生的执行回执用于交互提示，最终 Session 与历史日志从服务端查询。教师端不代理学生日志上传，也不通过屏幕流推断 Session 的权威状态。学生控制连接失效时显示失联和结果待确认，不能以超时宣布原命令“未执行”后换新 ID 重发。

## 学生端身份：Electron 对外联网，Rust 本地守护

学生端所有网络通信均由 Electron 主进程或应用内 worker 完成。学生机不通过广播寻找服务器，也不让 Rust 连接服务器或教师。

| 对端 | 学生 Electron 发送 | 学生 Electron 接收 | 协议 / 触发条件 |
| --- | --- | --- | --- |
| 服务端 | 首次入网申请；日常启动、`bootId`、版本、能力报告；设备凭证续期/轮换 | 审批/设备身份、注册结果、兼容条件与新凭证 | HTTPS；启动时按安装配置连接固定服务端，按凭证生命周期维护身份 |
| 服务端 | 当前控制教师与适用策略查询 | 教师设备身份、地址/端口、控制代次/有效期；必需进程等策略 | HTTPS 查询，WSS 变化通知；启动、端点变更、连接失败或接管 |
| 服务端 | 目录/策略应用结果、新控制代次及新教师连接确认 | 校准结果 | 既有 WSS 版本化消息；完成实际应用后确认，持久审计另经日志/事件通道 |
| 服务端 | 本机锁定/解锁、Session 使用/暂停区间、关机、命令执行结果等业务事件 | 事件、关联审计日志和状态投影提交后的确认 | HTTPS `events` 批传；先落盘，重试保持原事件/命令 ID |
| 服务端 | 本机全部应用/SDK/网络日志；Rust 全部日志；安装/更新/回滚日志 | 已持久化日志 ID 集合、失败项 | HTTPS `/api/v1/logs/batch`；持续批传，断网/退出后恢复补传 |
| 服务端 | 画面订阅连接/执行状态 | 已授权订阅、教师身份与端点、有效期、变更和取消 | 既有 WSS 通知与确认；必要时 HTTPS 重新获取适用快照 |
| 服务端 | 更新检查、包下载/续传、更新阶段与结果 | 签名清单、安装包、兼容信息 | HTTPS；校验通过且满足维护条件后才安装 |
| 服务端 | 每 1 秒 ping | 匹配当前连接和序号的 ack | WSS；连续 20 秒无有效回应则锁机 |
| 当前控制教师 | 认证握手、本机状态、命令回执、每 1 秒 ping | 授权命令、匹配的 ack | 学生主动建立控制 WSS；同时验证教师身份、签名、目标、Session、代次与有效期 |
| 获授权监控教师 | 认证握手、画面、采集状态/错误 | 获授权范围内的订阅参数与取消 | 学生主动建立独立画面 WSS；慢消费者丢旧帧，不能丢待传日志 |

学生对服务器、当前控制教师分别计时，任一路连续 20 秒无有效应用层回应即锁机；另一条在线不能抵消。只读教师的画面连接不参与这一判定。学生端网络恢复后先校准状态并保持锁定，继续使用须教师重新授权。

Rust 的日志、状态和健康挑战通过带 ACL 的本地命名管道与 Electron 交换；`ReadLogs` / `AckLogs` 是本地持久交接接口，不是网络 API。Rust 可在 Electron 不可用时本地记录并请求关机，日志待应用恢复后上传。安装/更新执行器采用同样的离线日志交接方式。

## 只读教师屏幕订阅的完整通信

控制教师和只读教师共用以下订阅流程；两者在控制权限与健康监督方面保持独立。

1. 教师向服务端申请查看指定学生设备。服务端检查账号、机房、设备范围及画面权限，生成短期订阅授权，绑定订阅标识、学生设备、教师设备/账号、允许的画质参数与有效期。
2. 服务端向教师返回授权，并通过学生已有的 WSS 将授权和该教师的身份/登记端点发送给目标学生。学生重连时重新获取当前适用订阅；学生离线时教师看到“等待连接”，不能伪装成已收到画面。
3. 学生校验授权与目标身份后，主动连接该教师的画面 WSS。双方校验设备身份并绑定订阅，教师在授权范围内发送画面参数，学生直接传图。服务端只参与授权、寻址和状态，不转发图像。
4. 教师翻页、关闭监控或服务端撤销权限时发送取消/撤销通知；学生停止对应采集和传输。订阅到期未续期也停止；撤销通知不可达时由短期有效期兜底，不声称离线即时撤销。
5. 教师 IP 改变后先向服务端更新端点。学生获取服务端确认的新端点后重连；不能只因某地址提供了“教师接口”就信任它。画面重连不续期控制心跳，不自动解锁。

对应[入网、发现与订阅时序图](device-discovery.svg)。服务端可以同时授权多个教师查看同一学生，设备集合和连接数按实际容量配置，不写死教师或学生数量。

## 所有链路共用的确认与故障规则

| 通信类型 | 成功依据 | 断线、超时或重复时 |
| --- | --- | --- |
| 入网、目录、策略 | 经过身份校验的响应及当前版本/代次 | 重连并校准；旧 IP、旧代次或自报角色不产生新权限 |
| 教师业务写操作 | 服务端持久提交后的业务结果 | 使用稳定请求/幂等标识查询或重试；不重复创建 Session、占用或授权 |
| 机器命令 | 同一 `commandId` 的实际执行结果及服务端事件确认 | 超时标记结果待确认，查询原命令；重试不换 ID、不重复执行 |
| 日志/业务事件 | 服务端事务提交后的明确确认集合 | 本地持久缓存，原 ID 重发；部分确认仅回收已确认项，校验失败项隔离告警 |
| 画面 | 当前订阅下的序号、采集时间和有效帧 | 显示失效/不可用，丢弃过时帧；不把画面故障直接当作 Session 结束 |
| 应用层心跳 | 当前连接、序号、有效期匹配的 ack | 学生到服务端/控制教师各 20 秒阈值；教师到服务端 20 秒停用新操作；TCP 存活不等于应用健康 |
| 更新 | 清单签名与包校验、受控安装、本地健康及业务校准各阶段结果 | 包续传；不兼容保持锁定；安装失败按计划回滚；全部阶段日志补传 |

客户端与服务端各自记录其产生的全部日志并归集到服务端，但不强制把每个心跳包或图像帧复制成日志。凭证、人脸资料和原始图像不能通过日志泄漏。日志接收/持久化不递归生成同等数量的新日志，传输失败用有限状态变化记录。

## 部署时需要放通的网络

| 发起方 | 目标 | 放通用途 |
| --- | --- | --- |
| 教师 / 学生 | 固定服务端地址及配置的 TLS 端口 | HTTPS API、WSS、日志/事件上传、更新下载；若文件服务独立部署，另外登记其受信任端点 |
| 学生 | 服务端目录中获授权教师的 TLS 监听端口 | 控制 WSS 与独立画面 WSS；教师动态 IP 变化后防火墙策略仍须覆盖授权网段/应用 |
| 服务端应用 | PostgreSQL 本机/私网端点 | 数据库连接；客户端网段不得直接访问 |
| 服务端应用 | 实际采用的独立文件/备份服务 | 仅在仓库不使用本地目录时存在；按部署记录服务凭证和目标端点 |

具体端口在部署配置中固定，不在设计中虚构端口号。服务端发现不能穿透网段隔离；跨机房需实际路由与防火墙放行。首版无学生间通信、教师间业务直连、广播发现、Rust 远程通道或远程键鼠流；多教师协调都经服务端。

人脸算法/SDK 的外部联网需求尚未选定，不把云识别、互联网遥测或第三方更新源写成必需链路。若后续接入要求外部服务，应单独补充数据范围、调用身份和端点；当前清单覆盖三端已确定的通信及服务器配套存储连接。
